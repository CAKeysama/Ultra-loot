# Ultra Loot: test plan

Owner: QA & Release Engineer. Machine-readable status of each test: [`tests.json`](../tests.json).

## Strategy

Ultra Loot's main promise is that it never loses or duplicates items, FE or XP, and that operations are
transactional (*simulate, then commit*). The suite therefore has three layers:

| Layer | Tooling | Runs | Purpose |
|---|---|---|---|
| Unit | JUnit 5 through MDG `unitTest` (mod loaded, registries frozen) | `./gradlew test` | Pure logic: storages, modifier math, side mapping, transactional insertion, codecs |
| GameTest | NeoForge GameTests (`@GameTestHolder("ultraloot")`) | `./gradlew runGameTestServer` | Real-world behaviour: ticking machines, capabilities, chests, persistence |
| Manual | In-game checklist below | before every release | GUI, rendering, UX, multiplayer sync, compatibility with other mods |

```bash
export JAVA_HOME="C:/Users/conta/.jdks/jdk-21.0.13+9"
./gradlew test                 # unit tests; report: build/reports/tests/test/index.html
./gradlew runGameTestServer    # GameTests; exits non-zero when a required test fails; run dir: run/
```

### Conventions

- A test that exposes a gameplay bug is **not** weakened or disabled. Its display name starts with `[BUG-nn]`, it
  stays red until the bug is fixed, and the bug is listed below and in `tests.json`.
- Tests that change `Balance` statics restore them (`@AfterEach` in unit tests, `@AfterBatch` in GameTests).
- GameTests use the empty template `data/ultraloot/structure/empty.nbt`, 15x6x15 air, DataVersion 3955. It was
  generated by a small NBT script; to change the size, regenerate it with the same layout. The machine sits at the
  centre (7,1,7). A Tier I Loot Generator (range 5) therefore never reaches the neighbouring tests, which are at
  least 5 blocks away.
- The `ultraloot` GameTest batch lowers `lootBaseTicks`/`mobBaseTicks` to 10 ticks in `@BeforeBatch` and
  restores them in `@AfterBatch`.
- Loot Generator tests use the auto-discovered profile `minecraft:auto/chests/simple_dungeon`. Every roll of that
  table yields items and it has no exploration maps. Most tests use target mode `ANY_INVENTORY`, so they do not
  depend on data-pack tags. One test covers the default `STORAGE_ONLY` mode, which needs the block tag
  `#ultraloot:storage_targets`.

### GameTests (`gametest/UltraLootGameTests`)

Loot Generator: fills a chest in range (items in chest = items generated, FE spent = operations × cost, no item
entities); range boundary (chest at distance `range` filled, chest at `range+1` untouched); full chest skipped,
another one filled; no FE spent while every target is full (`TARGETS_FULL`); no targets → `NO_TARGETS`, no FE;
round robin across 2 chests; face rules (Item Target face used, Energy Input face → `FACE_DISABLED`; a face set to
None is not used); double chest counted once; default `STORAGE_ONLY` mode; `NO_ENERGY`; unknown profile rejected
→ `NO_PROFILE`; capabilities per face; full NBT persistence round trip.

Mob Loot Generator: zombie Mob Card + XP + FE produces drops, XP and FE match operations × cost, no entity or item
is ever added to the world; `OUTPUT_FULL` with FE/XP kept; export through the Item Output face (bottom) into a chest
below; no export through other faces; `NO_XP`; `NO_MOB_CARD` and card validation; XP bottle intake; Range Card orb
collection (and none without the card); capabilities per face (FE, XP, fluid adapter, XP item slot, extract-only
output); full NBT persistence round trip (XP, FE, card, cards, output, XP slot, sides, statistics).

The Range Card orb test spawns its orb with zero motion. Vanilla orbs spawn with random motion and could drift out
of the 2-block radius before the 20-tick collection pass, which made the test flaky (1 failure in 5 runs).

Loot profiles:
- The `ultraloot:fishing` profile fills a chest, and no entity of any kind is ever added to the test area, so the
  detached `FISHING_BOBBER` never enters the world.
- Auto-discovered profiles use `Balance.autoProfileMinTier` and `autoProfileEnergyMultiplier`, and a Tier I machine
  cannot select one. **At present this test only logs a skip and passes**: the shipped profiles cover every vanilla
  `chests/*` table, so no `*:auto/*` profile exists. The unit test `LootModelTest.autoChestProfileIdFormat` still
  checks the gating values on `LootProfile.autoChest`.
- No profile uses the exploration-map tables `chests/shipwreck_map`, `underwater_ruin_small` or
  `underwater_ruin_big`.
- A Tier I machine cannot select the min-tier-4 profile `ultraloot:end_city_treasure`; its status stays
  `NO_PROFILE` and it spends no FE.

Mob simulation: 40 simulated magma cube kills with Looting III drop magma cream, because the simulator now uses a
size-2 cube. 40 simulated slime kills drop slime balls, because a size-1 slime is still used. Neither run adds an
entity to the world.

## Manual in-game checklist (not automatable)

Run in a dev client (`./gradlew runClient`) with a creative and a survival player, and once on a dedicated server
with two clients.

1. **GUI layout**: both machines, all 4 tiers. Tabs open/close, no overlapping widgets, text fits in English, tooltips
   on every button, the energy/XP bars match the numbers.
2. **Upgrade slots**: shift-click cards into the right slot, a second card of a category is refused, removing a
   card updates speed/energy/range in the GUI immediately.
3. **Side configuration tab**: left/right click cycles modes, colours match the faces, the configuration survives
   rotation (place facing each direction) and chunk reload.
4. **Profile selector**: list scrolls, auto profiles appear, locked profiles (min tier) cannot be selected by a T1
   machine, the selection persists after relog.
5. **Scan list**: chests in range appear with distance/free slots; FULL / NOT_STORAGE / FACE_DISABLED states shown;
   Rescan button works.
6. **Filters**: buttons disabled without a Loot Card; removing the Loot Card resets the filter to ALL.
7. **Active texture**: the front lights up while running and switches off ~2 s after it stops; no flicker when
   FE hovers around the cost.
8. **Mob cards**: imprint a zombie and a modded mob with a blank card; a boss / blacklisted mob is refused with a
   message; the card tint matches the spawn egg.
9. **Experience capsule**: sneak-use stores, use releases; capacity 1395 (30 levels); a capsule in the XP slot drains
   into the tank and an empty capsule can be extracted by a hopper on an XP Input face.
10. **Breaking machines**: all items (cards, output, card, XP slot, overflow) drop; stored XP drops as orbs.
11. **Multiplayer**: two players with the GUI open see the same values; a modified client cannot set invalid
    sides, filters or profiles (server validation).
12. **Compatibility**: FE from a modded cable (e.g. Mekanism / Thermal) respects the per-tier rate; an experience
    fluid from a mod that tags `c:experience` fills the XP tank; hoppers/pipes extract from Item Output faces only.
13. **Performance**: 50 Loot Generators with Range III in one area. Check `/neoforge tps` and the profiler, and
    confirm there is no per-tick world scan.

## Known bugs found by the suite

Both were fixed by the code owners during the QA pass. Their tests now pass and stay as regression tests; the display names end in `(regression BUG-nn)`.

| Id | Severity | Location | Reproduction | Fix |
|---|---|---|---|---|
| BUG-01 | minor | `machine/SideConfiguration#fromArray` | Persisted side ordinal 99 or -1 becomes `NONE`, because `SideMode.byOrdinal` maps it to `NONE` and every family allows `NONE`. The class contract says it falls back to the family default | **fixed**: the range is validated before mapping; otherwise the reset default is kept |
| BUG-02 | minor, visible to players | `upgrade/UpgradeModifiers#energyPerOperation` | `Math.ceil` on the raw double product: T1 + Range I costs 881 FE instead of 880, Quantity II 1761 instead of 1760, T3 + Speed II 4051 instead of 4050 | **fixed**: `Math.ceil(cost - 1e-6)` |
